
# ShipIt — консольный симулятор доставки посылок на Java

**ShipIt** — учебное консольное приложение, моделирующее работу с посылками разных типов. Проект создан для практики Java Core, объектно-ориентированного программирования, обобщений и модульного тестирования.

Программа позволяет регистрировать отправления, рассчитывать стоимость доставки, распределять посылки по коробкам с ограничением веса и выполнять дополнительные действия для отдельных типов посылок.

## Возможности

- Создание трёх типов посылок: стандартных, хрупких и скоропортящихся.
- Расчёт стоимости доставки по весу и типу отправления.
- Размещение посылок в коробках с ограничением суммарного веса.
- Просмотр содержимого коробок.
- Имитация упаковки и доставки с выводом сообщений в консоль.
- Указание нового местоположения хрупких посылок (вывод сообщения о статусе).
- Проверка срока годности скоропортящихся отправлений.
- Интерактивное консольное меню.

**Важно:** программа моделирует эти операции локально; настоящей службы доставки, сохранения статусов, базы данных и сетевого API в проекте нет.

## Типы отправлений

| Тип | Класс | Тариф | Особенности |
|---|---|---:|---|
| Стандартная | `StandardParcel` | 2 руб./кг | Базовая посылка |
| Хрупкая | `FragileParcel` | 4 руб./кг | Дополнительная упаковка, сообщение о местоположении |
| Скоропортящаяся | `PerishableParcel` | 3 руб./кг | Проверка срока годности |

Формула расчёта: **стоимость = вес × тариф типа посылки**.

При запуске приложения создаются три коробки: для стандартных отправлений (до 100 кг), хрупких (до 75 кг) и скоропортящихся (до 50 кг).

## Технологии и подходы

- Java Core
- ООП: абстрактные классы, наследование, переопределение методов и полиморфизм
- Интерфейс `Trackable`
- Дженерики: `ParcelBox<T extends Parcel>`
- Коллекции: `List`, `ArrayList`
- Консольный ввод с помощью `Scanner`
- JUnit 5 — модульные тесты

Проект не использует Spring, базу данных, Maven или Gradle.

## Как запустить

**Требования:** установленный JDK. Компиляция и запуск проверены на Java 21.

### Через терминал

Из корня репозитория выполните:

```bash
javac -encoding UTF-8 -d out src/parcels/*.java src/DeliveryApp.java
java -cp out DeliveryApp
```

Команды рассчитаны на Linux/macOS. В Windows удобнее воспользоваться IntelliJ IDEA.

### Через IntelliJ IDEA

1. Откройте проект в IntelliJ IDEA.
2. Укажите установленный JDK в настройках проекта.
3. Запустите метод `main()` класса `DeliveryApp`.
4. Выберите действие в консольном меню.

Пример: выберите `1`, создайте стандартную посылку весом `3` кг, затем выберите `3` для расчёта общей стоимости доставки. Программа выведет **6 руб.**

## Тестирование

В каталоге `src/test` находятся **12 тестовых методов JUnit 5**. Они проверяют:

- добавление посылки при допустимом весе, превышении лимита и точном совпадении с лимитом;
- проверку срока годности до, после и в день истечения;
- стоимость доставки для трёх типов посылок, включая нулевой вес.

В проекте отсутствует файл конфигурации Maven/Gradle, поэтому для запуска тестов через IntelliJ IDEA необходимо настроить зависимость **JUnit 5** и пометить `src/test` как каталог тестовых исходников. Автоматический запуск всех тестов в рамках этой проверки не выполнялся.

## Ограничения и возможные улучшения

Это учебная консольная модель. В текущей реализации:

- Посылка регистрируется в общем списке даже в случае отказа добавить её в коробку из-за превышения веса.
- Нет проверки на отрицательный вес и полноценной обработки неверного пользовательского ввода.
- «Отправка» выводит сообщения и не меняет состояние посылок; повторный вызов повторяет сообщения.
- Новое местоположение хрупкой посылки выводится в консоль, но не сохраняется.
- Данные существуют только во время работы программы.
- Срок годности задаётся условным номером дня, а не календарной датой.

Возможные направления развития: улучшить валидацию, разделить интерфейс и бизнес-логику, добавить статусы посылок, расширить тестовое покрытие и подключить Maven или Gradle.
